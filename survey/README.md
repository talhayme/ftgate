# Six public tool-calling datasets through `ftgate data`

What a trainer would silently do to the most-downloaded function-calling
SFT datasets on Hugging Face, measured with the target model's own
tokenizer and chat template rather than by eyeballing JSON.

**Reference model:** Qwen2.5-0.5B-Instruct (its tokenizer and template;
the family this project studies). Token counts and truncation are
template-specific — another model's template changes them, the structural
findings do not.

## Method

- **Sampling.** 1,500 rows per dataset through the `datasets-server` rows
  API: 15 windows of 100 rows at seeded, 100-aligned offsets across the
  `train` split, so the sample is not the head of the file. Byte-identical
  raw rows are dropped before anything else (the first hermes run had 385
  of them from overlapping windows — a sampling bug, fixed; the column
  `raw dups removed` keeps that honest).
- **Adapters.** None of the six is in `messages`+`tools` shape. Each has an
  adapter (`adapters.py`) and the adapter is part of what is measured:
  its parse failures are a column, and where a dataset's own format is
  lossy — glaive's tool-call arguments as a single-quoted string, xLAM's
  "no `default` means required" convention — the adapter keeps the quirk
  so the linter can see it. Datasets that write the tool signatures into
  their own system prompt (hermes, glaive) are flagged `tools_in_prompt`
  so the template does not render them a second time; Dolci keeps its
  signatures in a separate field, so for it the template renders them.
- **Lint.** `ftgate data` with `--model Qwen/Qwen2.5-0.5B-Instruct` at
  `--max-seq-len` 2048 and 4096. Every figure is a share of linted rows.

Reproduce: `python survey/hf_sample.py 1500 && python survey/run_survey.py`.

## What the numbers mean, dataset by dataset

**hermes-function-calling-v1.** The system prompt carries every tool
signature as JSON, so rows are long: median 1,838 tokens under the Qwen
template, 45% over 2,048. The part that matters: for **38% of all rows**
a 2,048 cutoff falls *before the final assistant turn* — the trainer keeps
the prompt and discards the answer. Without loss masking the row still trains — on the system prompt and the tool signatures, not on a call. With response-only masking (`assistant_only_loss` in TRL, `train_on_responses_only` in Unsloth; opt-in in both) it contributes exactly zero gradient. Either way the model is never shown the answer.
A fine-tune of a small model at the common default `max_seq_length=2048`
shows the model the answer in fewer than two thirds of this dataset, without
any warning. At
4,096 the problem disappears. Separately, 9.7% of rows end on a `tool`
message with no assistant reply after it: there is no answer to train on. Schemas and calls are internally consistent — zero
undeclared tools, zero missing required arguments.

**glaive-function-calling-v2** (original text format). Short rows, no
truncation issue. The format itself is the finding: `ASSISTANT: <functioncall>
{"name": …, "arguments": '{…}'}` — the arguments are a *string inside
single quotes*, which is neither JSON nor Python. The adapter recovers
them; a naive converter does not. Rows also split a reply into two
`ASSISTANT:` turns (a sentence, then the call); the adapter merges them.
1.4% of rows end on a function response.

**xlam-function-calling-60k** and **apigen-function-calling** (same
generator; apigen adds a `distilabel` subset in OpenAI tool shape). Single
turn, every row a call, no truncation at 2,048. 1.3–1.5% of rows call a
tool while omitting a parameter the schema marks required — by xLAM's
own convention, "no `default` means required". Looking at the rows, the
defaults are on the wrong parameters: `calculate_electric_field` gives
`charge` and `distance` a default of `8.854e-12` (vacuum permittivity)
and leaves `permitivity` with none, and the call then omits it. The
schema and the call disagree; a model learns whichever it is shown.

**glaive-function-calling-v2-sharegpt** (hiyouga's conversion). The
LLaMA-Factory roles (`function_call`, `observation`) convert cleanly and
the single-quote quirk is gone. 3.2% of rows are exact duplicates after
raw de-duplication — the conversion drops the system prompt, so rows that
differed only there collapse into one.

**Dolci-Instruct-SFT-Tool-Use** (AllenAI). Structured fields rather than
text: tool signatures in a `functions` field on the system message, calls
in a `function_calls` field as Python expressions (`get_user_feed(is_id=25081362)`,
dotted names like `instagram.get_user_feed`), results under an
`environment` role. Two findings. First, length: median 1,194 tokens but
p95 8,897 and a maximum of **334,792** — one `environment` turn is a
1.2 MB API dump (a Semantic Scholar response). 16.9% of
rows exceed 2,048 and **14.9%** are cut
before the final assistant turn; at 4,096 it is still 6.7%.
Second, 3.8% of rows contain a
call that is not a valid Python expression. Of 155 such lines in the
sample: 65 mix JSON into Python (`stableonly=true`), 52 have tool names
with spaces (`Historical Engagement Stats(...)`), 7 have hyphens
(`list-forms()`), 31 are a bare `null` where a call should be. The format
is declared as Python calls, and the rows teach the model two notations
at once.
Calls that do parse match the declared tools almost perfectly (one
undeclared name in 1,500 rows).

## Caveats

- 1,500 rows per dataset. Rates near 0.1% are one or two rows.
- Truncation figures are for the Qwen2.5 template. Llama-3 or Gemma
  templates render tools differently and will move the hermes numbers,
  though not from 38% to zero.
- The adapters are mine. The schema findings depend on reading each
  dataset's conventions correctly; the xLAM "no default = required" rule is
  stated in that dataset's documentation, the glaive argument-string quirk
  is visible in the raw text.
- An earlier version of this page called response-only masking "the default
  in Unsloth/TRL". It is not: TRL's `assistant_only_loss` defaults to `False`
  and Unsloth's `train_on_responses_only` is a helper you call. The rows
  affected are the same either way; what differs is whether they train on
  the prompt or on nothing.
